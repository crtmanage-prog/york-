# Бриф для бота: постоянное меню + упрощённое напоминание + «Мой абонемент»

## Часть 1 — Постоянное меню быстрого доступа

При входе в бота (на `/start`, и желательно закрепить постоянно, а не
только один раз) показать reply-клавиатуру с четырьмя кнопками:

```
🏠 Мой кабинет      🔁 Перенести урок
💬 Связь с менеджером   🎫 Мой абонемент
```

Поведение каждой кнопки:

- **🏠 Мой кабинет** — просто ссылка на `https://weyork.online/login.html`.
  Ученик логинится обычным способом (логин/пароль) — никакой магической
  ссылки, токена или автовхода не нужно, встроенных изменений в
  `login.html`/`cabinet.html` не требуется.
- **🔁 Перенести урок** — то же самое действие, что уже делает команда
  `/reschedule` (генерация токена в `reschedule_tokens`, отправка ссылки
  на `reschedule.html`). Просто ещё один способ вызвать ту же самую,
  уже готовую логику — новый код для самого переноса не нужен.
- **💬 Связь с менеджером** — статичная ссылка на `https://t.me/thearbeiter01`.
- **🎫 Мой абонемент** — см. часть 3 ниже, это новая логика.

## Часть 2 — Упрощаем напоминание об уроке (было — два уведомления, стало — одно)

Договорились не городить отдельное уведомление за 24–48 часов до урока
со ссылкой на перенос — раз перенос теперь всегда доступен через кнопку
в меню (часть 1), тащить его ещё и в таймed-уведомление избыточно:
ссылка всё равно не будет разрешена ботом, если урок ближе, чем
`CANCEL_HOURS = 24` часа, так что помещать её в уведомление за час до
урока было бы просто мёртвым пунктом.

Вместо этого — расширяем уже существующий cron `lesson-reminders`
(сейчас шлёт только учителю и админу за час до урока), добавляя туда
получателя-ученика:

```
Через час у вас урок с {teacher_name} ({time_ru}).
Не забудьте отправить домашнее задание, если ещё не сдали.

[🏠 Мой кабинет]
```

Без ссылки на перенос в этом сообщении — она здесь не имеет смысла
(поздно, 24-часовое окно уже закрыто).

## Часть 3 — «Мой абонемент» (новая логика подсчёта)

### Формула остатка — использовать ТОЧНО ту же, что уже в `cabinet.html`
(функция `computeRemaining`, строка ~1740), чтобы цифры не расходились
между ботом и личным кабинетом:

```js
function computeRemaining(payment, allLessons){
  if (!payment) return null;
  const linked = allLessons.filter(l => l.payment_id === payment.id);
  if (linked.length > 0){
    // отменённые и перенесённые НЕ считаются использованными —
    // занятие возвращается в абонемент
    const usedCount = linked.filter(l =>
      isLessonPast(l) && l.status !== 'cancelled' && l.status !== 'rescheduled'
    ).length;
    return (payment.lessons_included || 0) - usedCount;
  }
  return (payment.lessons_included || 0) - (payment.lessons_used || 0);
}
```
Переведи на SQL/Deno как удобнее технически, но именно эту логику —
включая то, что отменённые/перенесённые уроки НЕ считаются использованными.

### Что показывать по кнопке «🎫 Мой абонемент»
Взять активный (`payments.status = 'active'`) платёж ученика, посчитать
остаток по формуле выше, и ответить текстом:

```
🎫 Твой абонемент

Осталось занятий: {remaining} из {lessons_included}
```

Дата `valid_until` нигде в этой задаче не показывается и не участвует —
ни здесь, ни в напоминании из части 4. Только количество занятий.

Если активного платежа нет вообще — короткий ответ с кнопкой
«💬 Связь с менеджером», без цифр.

## Часть 4 — Новое напоминание: абонемент подходит к концу

Отдельный cron (по аналогии с `lesson-reminders`), раз в день, находит
учеников, у кого остаток по формуле из части 3 равен **1** (последнее
занятие) — и шлёт сообщение:

```
🎫 Твой абонемент скоро закончится

Осталось занятий: 1

Чтобы продолжить заниматься без перерыва — продли абонемент.

[🔄 Продлить абонемент]
```

Кнопка «Продлить абонемент» ведёт на тот же `https://t.me/thearbeiter01`,
что и «Связь с менеджером» — самой покупки/продления через бота нет,
всё решается в переписке с менеджером, просто формулировка кнопки
здесь конкретнее под момент (человек хочет продлить, а не абстрактно
«связаться»).

Дата `valid_until` в этой задаче не участвует вообще — триггер только
по количеству оставшихся занятий.

Важно: не слать это же уведомление повторно каждый день подряд одному
и тому же ученику по одному и тому же платежу — одного напоминания за
весь период (например, отметкой в `payments` или отдельной таблицей
логов уведомлений) достаточно, иначе это будет выглядеть как спам.

## Что НЕ входит в эту задачу
- Сама покупка/продление абонемента — это по-прежнему через менеджера
  вручную, бот не принимает оплату
- Логика самого переноса — не меняется, только способ вызова (кнопка
  в меню равнозначна команде)
- Тестовые правила — те же, что и раньше: только на chat_id Катерины,
  тестовые профили с откатом после теста
